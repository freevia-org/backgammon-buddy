Status: **22 distinct E2E cases passed across the core run and corrected phone-flow rerun.** No remaining failure was observed in this tested scope. This is simulator evidence, not signed-device or App Store acceptance.

The ordinary `lib/main.dart` app was subsequently rebuilt and launched successfully with `flutter run --no-resident`, and its running simulator process was verified. It is left running. Native Firebase logs report missing configuration, consistent with this local build having no cloud/telemetry configuration.

The initial on-device run passed 20 cases and failed two new harness assertions. The harness incorrectly assumed debug builds default to an unconfigured online backend and looked for an obsolete Close button on the inline tutor panel. The corrected phone rerun passed both cases. The phone fixture explicitly overrides online configuration to null to reproduce the unsigned release build's offline state; it does not test a cloud backend. No production app change was needed for these two failures.

The new harness also passed static analysis. Earlier host tests (1,314 passed, 7 skipped) are a separate baseline.

## Simulator recovery

The initial runtime was unstable: missing runtime paths, failed first-boot migrations, dynamic-loader stalls and lost VM connections prevented assertions from running. With the user's approval, the shared CoreSimulator service was restarted. Two runtime builds shared the same iOS 27.1 identifier. The older/mismatched `24A94425` image was unmounted without deleting it; only the SDK-matching `24A94232` runtime remained active. A fresh dedicated simulator then completed boot in 20 seconds and supported the passing tests.

Device Hub access was initially unavailable. The automated results above come from Flutter integration tests executing in the simulator. Manual visual checks were subsequently completed as described below.

## Limits

Live Firebase/cloud matches, real Wi-Fi peer discovery, optical QR scanning, physical camera/voice behavior, native share-sheet delivery, exhaustive localization/accessibility review and physical-device acceptance remain untested. The nearby end-to-end match uses real sockets on simulator loopback, not two physical devices. The AI UI flow ends through surrender; it is not a naturally completed full AI game.

## Reproduce

The archives staged in `app/ios/Frameworks` currently target the simulator. Restage **both** device archives before a physical-device build. From `app/`, with PATH and RUBYOPT from `ios-local-build.md`:

```sh
printf 'ENABLE_DEBUG_DYLIB = NO\n' > /private/tmp/backgammon-simulator-debug.xcconfig
export XCODE_XCCONFIG_FILE=/private/tmp/backgammon-simulator-debug.xcconfig
export FIREBASE_ANALYTICS_WITHOUT_ADID=true
flutter test integration_test/ios_e2e_test.dart \
  -d B0AB93A1-E17C-4A71-AD85-EE2F1B51FA57 --no-pub --reporter expanded
```

Logs are retained in `app/build/ios-e2e/`, particularly `backgammon-ios-e2e-after-restart.log` (20 core passes plus the two initial harness failures) and `backgammon-ios-phone-e2e.log` (both corrected phone flows passed).
